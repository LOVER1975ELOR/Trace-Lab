Environment for a fresh experiment
  Original system: Ubuntu 24.04.5 LTS, x86-64, kernel 6.17.0-40-generic,
  perf 6.17.13, LTTng Tools 2.13 and compatible LTTng kernel modules.
  The machine used LTTng Modules 2.13.23 built for this kernel in Lab 1.

  Required tools: Bash, sudo, matching perf, lttng, Babeltrace (the babeltrace

    findmnt /sys/kernel/tracing

  Run the scripts as your normal user with sudo access; they elevate the

Preserve the submission and create a fresh run
  From the extracted lab3 directory, in Bash:

    lab3_package="$PWD"
    lab3_rerun=$(mktemp -d "$lab3_package/../lab3-rerun-XXXXXX")
    cp -a scripts src "$lab3_rerun/"
    mkdir -p "$lab3_rerun/reference/Lab 3/src" "$lab3_rerun/logs/runs" "$lab3_rerun/notes"
    cp "$lab3_package/src/deadlock_m" "$lab3_rerun/reference/Lab 3/src/deadlock_m"
    cd "$lab3_rerun"
    chmod u+x src/deadlock_m

  This supplies the reference copy required by script 02's binary comparison.
  The archive checksum verifies the original supplied executable. Script 01
  is retained as the original repository-download/preparation record; the
  packaged executable allows a fresh run to begin directly with script 02.

Analyze a fresh run
  Import the two new GUI trace directories into Trace Compass. Obtain the
  new PID and worker TIDs from sched_process_fork records mentioning
  deadlock_m. Locate those worker TIDs in Uaddr vs Waiter to identify the
  new futex addresses and compare the short and long wait intervals.

  Script 06 has the ORIGINAL addresses in ADDR_A and ADDR_B. Update those two
  variables in the fresh copy of scripts/06_analyze_futex_addresses.sh with
  the addresses from the new 8-second trace, then run:

    bash scripts/06_analyze_futex_addresses.sh

  Fresh executions have their own PIDs, addresses, timing, and event counts.
  Compare the behavior and relationships within each execution. The report
  and saved analysis files describe the original captured executions.
